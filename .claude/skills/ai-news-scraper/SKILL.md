# 每日AI早报 — 新闻抓取

## 时间要求

- **触发时间**：每天 9:30 AM
- **完成截止**：10:00 AM 前必须完成
- **预计耗时**：抓取 ~5 分钟 + AI 处理 ~12 分钟 = 总计 ~17 分钟

## 目标厂商

### 海外主要厂商
OpenAI、Anthropic、Google、xAI、NVIDIA、Meta

### 国内主要厂商
阿里云、火山引擎、DeepSeek、腾讯、智谱AI、MiniMax、月之暗面、华为

### 其他关注分类
其他厂商、自动驾驶、具身智能、AI出海、投资资讯、行业趋势&观点

### 自动驾驶重点关注厂商
文远知行、小马智行、Waymo、特斯拉

## 执行流程

### 第一步：定位三大早报源的最新文章

不要使用固定的文章 URL，而是每次运行时从各源站首页/栏目页找到最新的那篇日报文章。

**重要：抓取前检查发布时间。** 如果三篇日报中最新一篇的发布时间距离当前超过 20 小时 → 说明日报可能延迟发布或停更，需要询问用户是否继续抓取。如果在 20 小时以内 → 无需询问，直接抓取。

#### 1a. 36氪「8点1氪」

搜索入口：`https://36kr.com/search/articles/8点1氪`

找到标题包含「8点1氪」的最新一篇文章（通常排在搜索结果第一位），记录文章 URL 和发布时间。只取当天或昨天发布的最新一篇。

#### 1b. 爱范儿「早报」

栏目页：`https://www.ifanr.com/category/ifanrnews`

在页面中找到标题包含「早报」的最新一篇文章，记录文章 URL 和发布时间。只取最近 24 小时内发布的那篇。

#### 1c. 极客公园「极客早知道」

栏目页：`https://www.geekpark.net/column/74`

在页面中找到「极客早知道」栏目下最新的一篇文章，记录文章 URL 和发布时间。只取最近 24 小时内发布的那篇。

### 第二步：抓取文章全文

使用 Playwright 无头浏览器分别抓取三篇文章的全文内容，保存为原始 JSON：

```bash
cd "<项目根目录>"
python3 .claude/skills/ai-news-scraper/scripts/fetcher.py articles \
  --36kr "<文章URL>" \
  --ifanr "<文章URL>" \
  --geekpark "<文章URL>"
```

产出文件：
- `.claude/skills/ai-news-scraper/raw/daily_reports.json` — 三篇早报文章的全文

### 第三步：处理三大日报文章（最高准则）

**三篇日报文章中的 AI 相关内容是最高优先级，必须提炼并放入最终数据，不受 24 小时窗口约束。**（非 AI 内容如纯消费电子、纯汽车、社会新闻等仍然排除。）

读取 `raw/daily_reports.json`，对三篇文章的内容逐一处理。

#### 3a. 提取 AI 相关新闻条目

从每篇文章中识别所有与 AI 领域相关的新闻条目，判断标准：
- 涉及目标厂商（国内外厂商列表）的新闻
- 涉及大模型、AI 芯片、具身智能、自动驾驶、AI 应用、AI 政策等话题
- 排除纯消费电子发布（手机/耳机/笔记本等，除非有明确 AI 卖点）
- 排除纯汽车发布（新车上市/财报等，除非涉及自动驾驶/AI 技术）

#### 3b. 分类与提炼

对每条 AI 新闻：
1. **归类**：判断属于哪个厂商或分类
2. **标题**：保留原意，精炼表达，15-25 字
3. **摘要**：70-100 字，客观陈述关键数据和事实，不加日期前缀
4. **来源**：标注来自哪个早报源（36氪/爱范儿/极客公园）

#### 3c. 「其他关注」卡片标题规则（关键原则）

属于「其他厂商/自动驾驶/具身智能/AI出海/投资资讯/行业趋势&观点」分类的新闻，卡片标题**必须从新闻中提取具体的、可辨识的名称**，严禁使用分类名（如"其他厂商""具身智能""行业趋势&观点"）作为标题。

标题取法，按优先级：

1. **有厂商名字 → 用厂商名字**。如 `三星发布 Memory-Based 架构大模型 Meki`、`小米 MiMo-V2.5 系列 API 永久降价`
2. **有人物名字 → 用「人物名字 + title」**。如 `黄仁勋（NVIDIA CEO）：AI 时代讲故事和创造力才重要`、`Demis Hassabis (DeepMind CEO)：AI 离爱因斯坦还有多远？`
3. **有报告名称 → 用报告名称**。如 `QuestMobile：AI 原生 App 月活达 4.61 亿`
4. **融资事件 → 用被投公司名 + 轮次/金额**。如 `光轮智能完成新一轮融资，蚂蚁集团领投`
5. **行业数据/政策 → 用数据或政策核心内容**。如 `中国人形机器人全球市场占比超八成，年出货量 1.44 万台`

**判断标准**：读者看到标题就能立刻知道"这条新闻讲的是谁/什么"。

同一厂商/实体在同分类下有多条新闻时，合并为一个卡片，卡片标题使用该厂商/实体名称。例如"其他厂商"分类下有两条小米新闻 → 一张小米卡片内含两条新闻。

#### 3d. 理解新闻主体再归类（关键原则）

判断"这条新闻讲的是谁"，而非关键词匹配：
- 团队/投资人背景中提到某公司 ≠ 该公司新闻
- 引用某公司产品作为对比 ≠ 该公司新闻
- 多家公司合作/发布的新闻，判断**谁是动作发起方/主导者**，合作方只是被提及对象 ≠ 新闻主角
- 例如"新智具身融资，团队来自 Meta、华为"→ 主体是新智具身，归入「具身智能」或「投资资讯」
- 例如"支付宝发布 AI 新品，与 MiniMax、阶跃星辰达成合作"→ 主体是支付宝（发布方/主导者），归入「其他厂商」的支付宝卡片；MiniMax 只是合作方，不应归入 MiniMax

### 第四步：查找独立文章链接（关键步骤）

**日报文章本身的 URL 不能作为新闻链接使用。** 每条新闻必须找到独立的、只讲这一条新闻的权威文章链接。

对第三步提取的每条新闻：
1. 在四大补充站点（IT之家、量子位、机器之心）中搜索对应新闻的独立报道
2. 如果补充站点有对应文章，使用该文章的 URL
3. 如果补充站点没有，使用搜索引擎搜索新闻标题，找到权威媒体的独立报道链接
4. **质量要求**：链接指向的页面必须专门报道该条新闻，不能是日报整合页、列表页或分类页

> 如果实在无法找到独立链接，该条新闻应从日报文章中保留，使用能找到的最佳链接（优先补充站点，其次搜索引擎结果，最后才考虑日报链接）。

### 第五步：从补充站点查询遗漏新闻（24 小时窗口严格过滤）

日报处理完毕后，从三个补充站点查漏补缺。**这一步必须严格按 24 小时窗口过滤。**

补充站点：
| 站点 | URL |
|------|-----|
| IT之家 | https://www.ithome.com/ |
| 量子位 | https://www.qbitai.com/ |
| 机器之心 | https://www.jiqizhixin.com/ |
| 腾讯新闻 | https://news.qq.com/ |

#### 5a. 抓取补充站点

```bash
python3 .claude/skills/ai-news-scraper/scripts/fetcher.py supplementary
```

产出文件：`.claude/skills/ai-news-scraper/raw/news_raw.json`

#### 5b. 筛选与过滤

1. 从三个补充站点的首页/列表页中识别 AI 领域新闻
2. 排除与第三步日报已提取内容重复的新闻（标题相似或同一事件）
3. **24 小时窗口过滤**：逐条检查发布时间
   - 标记为"X小时前"或"今天" → 在窗口内 → 保留
   - 标记为"昨天" → 在窗口内（相对当天午夜抓取 = 前一天白天） → 保留
   - 标记为"前天"或更早 → **必须剔除**
   - 标记为具体日期如"05-26" → 与窗口起始日期对比，早于前一天的剔除
4. **复核**：过滤完成后，对所有保留条目做二次确认，确保没有"前天"或更早的内容混入

#### 5c. 提炼与补充

对通过过滤的新闻，按同样的标准提炼标题、70-100 字摘要、归类，补入对应厂商/分类的 `news` 数组。

### 第六步：合并去重

1. 将第三步（日报）和第五步（补充站点）的新闻合并
2. 标题高度相似或指向同一事件的视为重复，保留日报来源的条目（日报优先）
3. 去重后按厂商/分类归类
4. 每条新闻摘要不加日期前缀

### 第七步：处理榜单数据

#### 7a. OpenRouter（自动抓取）

```bash
python3 .claude/skills/ai-news-scraper/scripts/fetcher.py rankings
```

从返回内容中提取 "LLM Leaderboard" 区域的模型排名和 token 数量，写入 `rankings_raw.json`。

#### 7b. LMArena 与 ProductHunt（截图 OCR，手动提供）

由于两个网站均受 Cloudflare 保护，无法通过 Playwright 自动抓取，改为**人工截图 + AI 识图**方案。

**用户操作**：每天手动截取两个网页 → 保存到固定目录，覆盖旧文件：

```
项目根目录/榜单截图/
├── lmarena.jpg       ← LMArena 榜单页截图 (https://lmarena.ai/leaderboard/text)
└── producthunt.jpg   ← ProductHunt 首页截图 (https://www.producthunt.com/)
```

**AI 处理**：运行时检查上述两个文件是否存在：
- 文件存在 → 用 AI 视觉能力直接读取截图，识别并提取榜单数据（模型名/得分/产品名/分类/排名）
- 文件不存在 → 沿用上期 data.json 中的对应榜单数据

> 截图要求：LMArena 截取模型排名列表区域，ProductHunt 截取首页当日 Top 产品列表区域。PNG 或 JPG 均可。

### 第八步：写入数据文件

1. 按输出格式拼装完整 JSON（合并 news + ranking）
2. **日期使用前一天**：如今天 5月28日运行，date 写 "2026-05-27"
3. **摘要**：不加日期前缀
4. 写入 data.json：
   ```bash
   echo '<json>' | python3 .claude/skills/ai-news-scraper/scripts/helper.py write
   ```
5. 同步生成 data.js（支持 file:// 协议打开）：
   ```bash
   python3 -c "
   import json
   with open('data.json','r') as f: data=json.load(f)
   js='window.__RAW_DATA = '+json.dumps(data,ensure_ascii=False,indent=2)+';'
   with open('data.js','w') as f: f.write(js)
   "
   ```
6. 运行校验：
   ```bash
   python3 .claude/skills/ai-news-scraper/scripts/helper.py check
   ```

## 注意事项

- **最高准则——日报优先**：三大日报最新文章中的 **AI 相关新闻**必须全部提炼收录，不受 24 小时窗口约束。非 AI 内容（纯消费电子、纯汽车、社会新闻等）仍然排除。这是不可动摇的第一原则。
- **24 小时窗口约束补充站点**：从量子位、IT之家、机器之心补充查询时，必须严格按 24 小时窗口过滤，标记为"前天"或更早的一律剔除。补充完成后进行二次复核。
- **日期使用前一天**：每天 9:30 抓取，data.json 的 `date` 使用前一天的日期
- **来源链接严禁使用日报整合链接**。每条新闻的 `link` 优先使用独立文章 URL；实在找不到时，按"补充站点 > 搜索引擎 > 日报链接"的优先级降级使用，不因缺链接而舍弃日报新闻。
- **摘要不加日期前缀**
- **「其他关注」卡片标题禁止宽泛**：属于"其他厂商/自动驾驶/具身智能/投资资讯/行业趋势&观点"的新闻，标题必须用具体公司名、人物名+头衔、研究报告名等，严禁用"其他厂商""具身智能""行业趋势&观点"等分类名作为卡片标题。读者看标题应能立刻知道"这条新闻讲的是谁"
- **行业趋势&观点**分类指南：收录 AI 领域重要人士的访谈/言论、行业研究报告（如 QuestMobile、IDC、Gartner 等）、行业趋势预判、政策/统计数据（如人形机器人出货量等）。卡片标题视内容而定——人物观点用人物名+头衔（如"Demis Hassabis (DeepMind CEO)"），研究报告用报告机构名（如"QuestMobile"），数据/政策用核心内容提炼
- **宁缺毋滥**：纯 PR 稿、无新信息、重复报道直接跳过
- **时间字段** 使用相对时间（如"3小时前"、"昨天"）
- **tags** 每条新闻 1-3 个标签
- **没有新闻的厂商/分类**，news 数组留空 `[]`
- **榜单数据**：OpenRouter 自动抓取；LMArena 和 ProductHunt 因 Cloudflare 限制采用人工截图 + AI 识图方案，截图文件缺位时沿用上期数据
- **早报源未更新** 如果某个早报源当日尚未发布（页面无当日内容），标注并跳过，继续处理其他源
- **必须同步生成 data.js**：写入 data.json 后立即生成 data.js，确保 file:// 协议也能加载最新数据
